Container Là Gì?

• Container là một đơn vị phần mềm tiêu chuẩn đóng gói mã nguồn và toàn bộ các phụ thuộc (Dependencies, Libraries, Config) cần thiết để ứng dụng chạy độc lập.
• Triết lý của Docker: "Build Once, Run Anywhere" (Đóng gói một lần, chạy được ở mọi nơi từ máy tính cá nhân đến máy chủ Cloud).

2. So Sánh Chi Tiết: Docker Container vs Virtual Machine (VM)
Bảng So Sánh Kỹ Thuật Toàn Diện
Tiêu chí 🖥️ Máy ảo (Virtual Machine - VM) 🐳 Docker Container
Kiến trúc cô lập Ảo hóa phần cứng qua Hypervisor, mỗi VM có 1 Guest OS riêng biệt Ảo hóa cấp OS, dùng chung Kernel với Host OS qua Namespaces & Cgroups
Kích thước Rất lớn (Vài GB đến hàng chục GB do chứa cả hệ điều hành) Rất nhẹ (Vài chục MB đến vài trăm MB chỉ chứa runtime & app)
Tốc độ khởi động Chậm (Mất từ vài chục giây đến vài phút để boot hệ điều hành) Siêu nhanh (Khởi động trong vài giây hoặc mili-giây)
Hiệu năng (Overhead) Tốn nhiều CPU và RAM chạy hệ điều hành ảo Gần như bằng Native Process (hiệu suất CPU/RAM đạt 99%)
CƠ BẢN Lesson 02 • Docker image, container và registry
3. Bộ Ba Khái Niệm Cốt Lõi: Image, Container Và Registry
1. Docker Registry

• Là "chợ" hoặc kho lưu trữ trực tuyến chứa các Docker Image.
• Public: Docker Hub (chứa hàng triệu image có sẵn như Ubuntu, Nginx, MySQL, OpenJDK).
• Private: AWS ECR, GitLab Registry, Nexus.

2. Docker Image

• Là một gói đóng băng tĩnh (Read-Only Template) chứa code, runtime và công cụ.
• Được cấu tạo từ nhiều lớp dữ liệu xếp chồng lên nhau (Layered File System).
• Ví von: Giống như Class trong lập trình hướng đối tượng.

3. Docker Container

• Là một thực thể sống (Instance) được tạo ra và chạy từ Image.
• Có một lớp mỏng ghi được (Read-Write Layer) ở trên cùng.
• Ví von: Giống như Object được sinh ra từ Class.

CƠ BẢN Lesson 03 • Cài đặt Docker và kiểm tra môi trường
4. Cài Đặt Docker Desktop & Kiểm Tra Môi Trường
1. Hướng Dẫn Cài Đặt Các Nền Tảng

• Windows: Cài đặt Docker Desktop kèm tính năng WSL 2 (Windows Subsystem for Linux) để đạt hiệu năng tối ưu.
• macOS: Cài đặt Docker Desktop (chọn đúng bản chip Apple Silicon M1/M2/M3 hoặc Intel).
• Ubuntu / Linux Server: Cài đặt Docker Engine trực tiếp qua apt-get install docker-ce.

2. Bộ Lệnh Kiểm Tra Sức Khỏe Môi Trường
# 1. Kiểm tra phiên bản Docker Client & Server Engine
docker --version
docker version

# 2. Xem thông số chi tiết hệ thống (CPU, RAM, Storage Driver)
docker info

# 3. Chạy thử container mẫu để kiểm chứng hoạt động
docker run hello-world
Cơ Chế Hoạt Động Của Lệnh docker run hello-world

1. Docker Daemon tìm image hello-world ở máy local ➔ Nếu không thấy (Unable to find image locally).
2. Tự động kết nối lên Docker Hub để tải (Pulling from library/hello-world).
3. Khởi tạo một Container mới từ image vừa tải ➔ Chạy tiến trình in thông điệp ra màn hình ➔ Tiến trình kết thúc và container tự dừng.

CƠ BẢN Lesson 04 • Các lệnh Docker cơ bản trong vòng đời container
5. Sơ Đồ Vòng Đời Của Một Container (Container Lifecycle)
Các Trạng Thái Chính Của Container
CreatedContainer vừa được khởi tạo từ image nhưng chưa bắt đầu chạy
RunningTiến trình chính đang thực thi, CPU và RAM đang được cấp phát
PausedTiến trình bị đóng băng tạm thời qua lệnh docker pause
Stopped (Exited)Tiến trình kết thúc, không tốn tài nguyên CPU/RAM nhưng vẫn còn ổ đĩa
DeletedDữ liệu container bị xóa hoàn toàn khỏi hệ thống qua docker rm
⚠️ Quy Tắc Vàng Về Vòng Đời Container

• Một container chỉ sống khi tiến trình chính (PID 1) của nó còn chạy.
• Nếu tiến trình chính hoàn thành hoặc bị lỗi kết thúc ➔ Container sẽ chuyển ngay sang trạng thái Exited.
• Ephemeral (Tính ngắn hạn): Container có thể bị hủy và tạo lại bất kỳ lúc nào, dữ liệu muốn giữ lâu dài bắt buộc phải dùng Docker Volume.

CƠ BẢN Lesson 04 • Các lệnh Docker cơ bản trong vòng đời container
6. Bảng Lệnh Thao Tác Với Docker Image
1. Tải & Liệt Kê Image
# Tải image từ Docker Hub (Mặc định tag :latest)
docker pull nginx
docker pull openjdk:17-jdk-alpine

# Xem danh sách các image hiện có trên máy
docker images
docker image ls

# Tìm kiếm image công khai trên Docker Hub
docker search mysql
2. Gắn Thẻ Tag & Xóa Image
# Đặt lại tên/tag cho image để chuẩn bị push
docker tag my-app:v1 myrepo/my-app:v1.0

# Xóa một image khỏi máy local
docker rmi nginx
docker image rm <image_id>

# Dọn dẹp tất cả image rác không dùng (Dangling)
docker image prune -a
Quy Tắc Đặt Tên Docker Image

Cấu trúc chuẩn: [registry_host/][username/]repository_name:tag
• Ví dụ: nginx:alpine (Tên image: nginx, phiên bản nhẹ: alpine).
• Nếu không chỉ định :tag, Docker sẽ luôn tự động gán là :latest.

CƠ BẢN Lesson 04 • Các lệnh Docker cơ bản trong vòng đời container
7. Lệnh Khởi Chạy & Quản Trị Container (docker run)
Lệnh Khởi Chạy Kinh Điển Cần Nhớ: docker run
docker run -d -p 8080:80 --name my-web-server nginx
Tham số (Flags)Ý nghĩa thực thi
-d (Detached mode)Chạy container ngầm dưới nền, giải phóng cửa sổ dòng lệnh terminal
-p 8080:80 (Port mapping)Ánh xạ cổng: Port Máy Thật (Host):Port Container (Mở http://localhost:8080)
--name my-web-serverĐặt tên gợi nhớ cho container thay vì để Docker tự sinh tên ngẫu nhiên
-e KEY=VALUETruyền biến môi trường vào container (vd: -e MYSQL_ROOT_PASSWORD=123)
--rmTự động xóa sạch container khi container dừng chạy
Xem Danh Sách Container
# Chỉ xem các container ĐANG CHẠY
docker ps

# Xem TẤT CẢ container (cả đang chạy và đã dừng)
docker ps -a
Dừng, Bật Lại & Xóa Container
# Dừng container an toàn (Gửi tín hiệu SIGTERM)
docker stop my-web-server

# Khởi động lại container đã dừng
docker start my-web-server

# Xóa container (Bắt buộc phải stop trước)
docker rm my-web-server
NÂNG CAO Lesson 05 • Kiểm tra log và truy cập container (logs, exec)
8. Kiểm Tra & Giám Sát Log Container (docker logs)
Cơ Chế Ghi Log Trong Docker

• Trong container, bất kỳ thông tin nào được ứng dụng in ra màn hình tiêu chuẩn (STDOUT hoặc STDERR) đều được Docker Daemon tự động bắt giữ và lưu trữ dưới dạng log.
• Đây là chuẩn mực quan trọng nhất của kiến trúc Cloud-Native / 12-Factor App: Xem log như một luồng sự kiện liên tục (Event Streams).

Các Lệnh docker logs Thực Chiến
# 1. Xem toàn bộ log từ trước tới nay
docker logs my-web-server

# 2. Theo dõi log thời gian thực (Follow log realtime)
docker logs -f my-web-server

# 3. Xem 100 dòng log gần nhất
docker logs --tail 100 my-web-server

# 4. Xem log kèm mốc thời gian chi tiết (Timestamp)
docker logs -t --tail 50 my-web-server
💡 Mẹo Xử Lý Sự Cố (Troubleshooting) Khi Container Không Bật Lên Được

Khi gõ docker ps không thấy container đâu (bị sập ngay khi chạy):
➔ Gõ ngay lệnh: docker ps -a để lấy mã Container ID.
➔ Gõ lệnh: docker logs <container_id> để đọc thông báo lỗi chi tiết (vd: Sai mật khẩu DB, port bị trùng, thiếu biến môi trường).

NÂNG CAO Lesson 05 • Kiểm tra log và truy cập container (logs, exec)
9. Truy Cập Vào Bên Trong Container (docker exec)
Cú Pháp Lệnh docker exec
# Mở terminal tương tác bên trong container
docker exec -it my-web-server bash

# Nếu container không có bash (vd Alpine Linux):
docker exec -it my-web-server sh
-i (interactive)Giữ cổng đầu vào STDIN luôn mở để nhận phím gõ
-t (tty)Cấp phát một màn hình Terminal ảo để thao tác dòng lệnh
bash / shChương trình dòng lệnh muốn thực thi bên trong container
Thao Tác Trực Tiếp Bên Trong Container
# Kiểm tra mạng và kết nối IP
cat /etc/hosts
ip a

# Kiểm tra file cấu hình
cat /etc/nginx/nginx.conf

# Thoát khỏi container trở về máy thật
exit

✅ Lưu ý: Lệnh exit chỉ thoát phiên shell, container vẫn tiếp tục chạy bình thường ở chế độ nền!

Tầm Quan Trọng Trong Văn Hóa DevOps

Docker là viên gạch nền tảng đầu tiên trong quy trình CI/CD. Đóng gói ứng dụng vào Docker Container giúp việc kiểm thử tự động, chuyển giao mã nguồn và triển khai lên cụm Kubernetes diễn ra mượt mà, loại bỏ 100% rủi ro sai lệch môi trường.
